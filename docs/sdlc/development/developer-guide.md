<!-- sdlc:auto:start overview -->
This is 'event bookingf', an event booking app generated by the Quorq AI SDLC platform as two separate applications in one repo. The frontend is a Vite + React 19 single-page app containing every approved screen, currently rendering seeded sample data rather than live API calls. The backend is a Spring Boot 4.1 (Java 21, Maven) service that, at this point, only exposes a health check endpoint and stub scaffolding -- no product architecture had been approved yet when it was generated. docker-compose.yml provisions the supporting infrastructure (PostgreSQL, two Redis instances, Meilisearch) the approved stack calls for, though the backend code itself doesn't wire most of these in yet.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite 6, React 19, TypeScript 5.6)
- Java 21 JDK
- Maven (via the included mvnw wrapper -- no separate install needed)
- Docker and Docker Compose (for Postgres/Redis/Meilisearch, and for the backend's own Dockerfile)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Copy .env.example to .env and fill in any required values
3. (Optional) Start supporting services: docker-compose up -d
4. cd frontend && npm install
5. cd backend: no install step needed -- sh mvnw will fetch dependencies on first run

<!-- sdlc:auto:start conventions -->
- Frontend screens are generated from an approved design and intentionally still run on seeded sample data; src/lib/api.ts is the seam for wiring a screen to the real backend
- API calls go through apiFetch in src/lib/api.ts, which sends a bearer token (session token first, falling back to a shared API secret)
- Backend uses the Maven wrapper (mvnw) exclusively, not a global mvn install
- Backend formatting/style enforced via Spotless (Google Java Format) and Checkstyle, run as Maven goals
- Backend falls back to an in-memory H2 database when DATABASE_URL is not set, instead of requiring Postgres for local runs
- Hibernate ddl-auto is set to 'update' only (additive schema changes), explicitly flagged as temporary until Flyway migrations are introduced
- Frontend lint/format enforced via ESLint and Prettier (.prettierrc, eslint.config.js)
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start or can't reach a database | Leave DATABASE_URL unset to fall back to the in-memory H2 database, or run docker-compose up -d to provide PostgreSQL on localhost:5432 |
| `npm run build` succeeds but the app fails type checks later | Run `npm run typecheck` (tsc --noEmit) separately -- build does not typecheck |
| Playwright e2e tests fail to launch Chromium | Run `npm run test:e2e:install` first to fetch the Chromium browser |
| Docker health check fails inside the backend container | The image has no curl/wget/Python; it uses the compiled docker/HealthCheck.java via the `aisdlc-health` script -- ensure that build step completed |
| Frontend API calls fail with 401/unauthorized | apiFetch sends VITE_API_SECRET_KEY as a bearer by default; ensure it matches the backend's configured secret, or set a session token via setSessionToken after login |
<!-- sdlc:auto:end troubleshooting -->
